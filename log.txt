Part 1: Architecture (Gemini-adapted)
1.1 Principles
Code decides, the model perceives. Gemini only turns PNG/PDF files and ambiguous request text into schema-constrained JSON facts with a quote and a confidence. Status, steps and ordering are deterministic code.
Quota-first design. Every model call must be justified. Run deterministic parsing first, call a model only for what parsers can’t read, and cache everything on disk.
Time is a hard boundary. One “as of audit_at” gate. Nothing captured after it is visible. A capture at exactly audit_at is allowed.
Claims aren’t proof. reported_status, reported_result and activity logs are leads. Snapshots, replicas, configs and consoles are proof.
Grounded links only (decoys exist). No hardcoded case IDs, resource IDs or label tables.
1.2 Pipeline
deletion_requests.csv
  → [A] Intent gate
        Tier 1: multilingual rule/keyword + negation (no model)
        Tier 2: only uncertain requests, sent in BATCHES (e.g., 20-30 per call) to Flash-Lite
        CLASSIFY_REQUEST events corroborate only
  → [B] Temporal identity graph (identities + audit log + linking events)
  → [C] Evidence catalog, cached by file hash, one normalized record schema
        SQL/JSON/logs/TXT → deterministic parsers (zero model calls)
        PNG/PDF (~15 files) → Gemini Flash multimodal, ONE call per file, once
  → [D] As-of selector (latest capture ≤ audit_at containing the resource's state)
  → [E] State reconstruction (per-copy, drift, field-level exposure, flows, backups, timeline)
  → [F] Policy engine (deletion_rules.csv, conditions from evidence)
  → [G] Status decider → [H] Planner (conventions from a data file) → [I] Validator
  → output.csv + per-case decision records + usage ledger
1.3 Gemini integration layer (new)
Concern	Design
Model roles	Two configurable roles: VISION_MODEL (a Flash-class multimodal model) for images and PDFs, and BULK_MODEL (a Flash-Lite-class model) for batched intent checks. Both come from env vars, with an optional fallback chain.
Model discovery	At startup, list the models your key can use and pick the configured IDs. If one isn’t available, fall back and record which model actually ran, so the usage report is truthful.
Structured output	Use the API’s JSON response schema (constrained output) for every call, then validate again in code. Reject and retry malformed output once, then mark the fact “unknown”.
Files	Send PNGs and PDFs directly as inputs, one file per call, and ask for a table of resource IDs, identifiers, states and quoted text. Never ask for a verdict.
Batching	Intent: many requests per call, returning {case_id, label, quote, confidence}. Prefer fewer, larger calls over many small ones.
Quota guard	A central client that tracks calls per minute and per day, sleeps and retries with backoff on 429, persists a “budget used today” counter, and stops cleanly when the daily cap is hit.
Resumable runs	Cache every response on disk (keyed by file hash or request-batch hash plus prompt version). A rerun makes zero new calls, so you can spread work across days.
Determinism	Temperature 0, fixed prompts in code/prompts/*.md, thinking budget minimized where configurable, and cached results are the source of truth for the final run.
Metering	Log provider, model actually used, input tokens, output tokens (including thinking tokens if reported), latency and cache hit/miss for every call.
Prompt-injection hygiene	Wrap evidence text as data. Ignore any instructions inside files.
